# The iOS documents are not in this repo

**`SWIFT-HANDOFF.md`, `SWIFT-SPEC.md` and the six `ios-specs/` surface documents live in
`github.com/imagine-greatly/kristy-ios`, under `docs/`.** They were removed from here on
2026-08-08. This file is the pointer, and it is deliberately a pointer rather than a copy.

## Why they were deleted rather than kept in sync

They were copied to `kristy-ios` on 2026-08-07 and the originals were never removed, so for
a day there were two of each and nothing keeping them equal. They diverged immediately —
measured before deletion:

| document | here | `kristy-ios` |
| --- | --- | --- |
| `SWIFT-HANDOFF.md` | 263 lines, dated 2026-08-05 | 702 lines |
| `SWIFT-SPEC.md` | 639 lines | 756 lines |
| `ios-specs/` (six files) | 3,968 lines | 4,405 lines |

The copy here predated **the Counter being built, shop mode, the scan card and the whole of
onboarding.** It still described the trips-import hold as "ahead 2" and knew nothing about the
generated-card corpus, the read meter, or the front door.

**The failure mode this closes is specific and it had already been set up.** Server work
happens in this repo, so a session doing server work opens `docs/` here — the natural file —
and reads a version of the state that is three features stale, with nothing on the page saying
so. The scan surface makes it concrete: building it means reading `scan.md`, and there were
two of those, 10 lines apart, with no way to tell from inside either one which was current.

That is this project's oldest defect wearing a new coat: **documentation that reads as
verified precisely because it is written down.** Two statements of one thing drift, and only
one of them gets updated. The fix for a duplicated document is never a sync discipline — it is
one copy and a pointer.

## What stays here, and why

- **`api-shapes.generated.md`** is generated by `server/scripts/buildApiShapes.js` **into this
  repo**, out of `server/routes/`. Its source of truth is here, so it belongs here. The copy in
  `kristy-ios` is the mirror, and it was byte-identical at the time of this split.
- **`PASS3-HANDOFF.md`, `DUPLICATION-SURVEY.md`, `LIST-CREATION-AUDIT.md`,
  `QUANTITY-PROPOSAL.md`, `SCHEMA-AUDIT.md`, `do-lines-review.md`, `PASS2-HANDOFF.md`** are all
  about the server and the React client. They never moved.

## Dangling references are expected, not stale

`server/scripts/buildApiShapes.js`, `server/lib/apiShapes.test.js`, `server/lib/listImport.js`,
`docs/DUPLICATION-SURVEY.md`, `docs/PASS3-HANDOFF.md` and this repo's `CLAUDE.md` all cite
`SWIFT-SPEC.md` or `SWIFT-HANDOFF.md` by name. Those citations are **correct and were left
alone** — they name a real document in the other repo, exactly as `docs/` paths in the iOS repo
name real files in this one. Rewriting them to carry a repo prefix would be churn on server
source, including files on the unpushed stack.
