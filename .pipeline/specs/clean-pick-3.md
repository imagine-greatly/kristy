## Answers

- Suite runtime: `npm test` is the full server suite (2862 at base); run it once at the end. `node --test server/test/acceptance/cleanPick3.test.js` alone first.
- Allowed reads: the files in owns and read_full, `server/lib/counterCardLint.js`, `server/lib/counterCards.js`, `server/lib/listMatch.js`, `server/scripts/twoLineCheck.js`, and `git show 2ab7f2f:<path>`.
- If a lint (lintCard, lintSections, lintRepeatedClaim, readability), a live guard (ic4b–ic8b, ca-3b, ca-5, k-series) or C9 goes red on a BECAME string: stop, report RED with the lint output or the matched slug, and name the nearest passing wording for that one string with its role kept (headline / cart / standard line). The acceptance test pins every string, so a rewording is a spec revision, not a builder call. Never loosen a lint. Pre-chosen fallbacks: frozen_pizza cart "Frozen pizza, whole wheat crust"; organ_meats cart (r1, probed: grass-fed in the cart routes to beef_grassfed_vs_grainfed, plural "meats" fails aliasNamesHead) "Pasture-raised beef liver or organ meat" is final.
- Lint facts checked by reading `counterCardLint.js` L1592–1866: `beef_raising` owns grass/grain-fed on butcher_counter_asking and organ_meats depth fields (none of their new tips or tier_note says grass-fed); `ruminant_grass_term` covers goat_sheep_dairy depth (its tip1 has no grass word); G3 needs its gloss only on meat/eggs_dairy fronts (organ_meats carries it; turkey_bacon’s base already did; lard_tallow and frozen_nuggets sit in bulk_pantry per the review table); G2 matches only "100% grass-fed" on dairy, and the dairy fronts say "Grass-fed"; CULINARY_LEXICON words appear in no new decision or cart.
- A test outside the routed list goes red on a batch id at an older ref: route it through `preCleanPick3` the same way, add it to the report as an owns addition. A red on a live guard is a content defect, not a routing case.
